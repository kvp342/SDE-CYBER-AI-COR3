## Uber (SDE intern and SDE-1)

A high-bar product company with engineering teams in Bengaluru and Hyderabad. Reports describe a hard online assessment, so speed on medium-hard problems decides who gets interviews.

### What candidates report

- Online assessment: reports describe 3 problems; one India report calls all three LeetCode-hard, another says the problems were framed as real-world Uber scenarios.
- Interviews: DSA rounds, plus design (LLD for SDE-1 in one report, high-level design in another) and a resume and behavioural discussion.
- Reports from 2025 disagree on difficulty for new-grad roles; many posts are for interns or SDE-2, which may overstate the fresher bar.

### How your plan prepares you

- The Hard pass and timed contests are what matter for the OA
- LLD pack: rate limiter and parking lot are close to the kind of design asked
- Run OA sets 5 to 8 and Mocks 3, 4 and 6

### Common mistakes

- Solving one OA problem perfectly and leaving the rest blank
- Over-engineering the LLD before the core works

### Questions to expect

- A graph or DP problem with a real-world story
- Design a component such as a rate limiter or a ride-matching queue

## Salesforce (AMTS)

Hires freshers as Associate Member of Technical Staff (AMTS), often through campus and pool drives in India. Reports describe a supportive, DSA-focused process.

### What candidates report

- Online assessment: a HackerRank coding test in a 2025 pool-campus report; one review describes 3 medium-hard problems on graphs, greedy and DP.
- Interviews: the same pool-campus report describes 2 virtual technical rounds on DSA, then an on-site hiring-manager round. Asteroid Collision and a sliding-window problem appear in reports.
- Candidates describe interviewers who guide you when you are stuck: think aloud.

### How your plan prepares you

- Graphs, greedy and DP from the Hard pass
- OA set 1 contains Asteroid Collision; redo it
- Prepare project stories for the hiring-manager round (Mock 8)

### Common mistakes

- Staying silent when stuck: the interviewers are reported to help if you explain your thinking

### Questions to expect

- Asteroid Collision
- A sliding-window or graph medium
- Walk me through a project you built

## Adobe (MTS-1)

Hires freshers as Member of Technical Staff (MTS-1), with large teams in Noida and Bengaluru. Reports stress writing complete code for classic algorithms, plus Core CS.

### What candidates report

- 2025 Noida reports: an HR screen, then several technical rounds (one report says four); questions included implementing KMP and Kadane's algorithm in full, the upper bound of an element in a sorted array, and generating all permutations.
- Older India reports: 2 data-structure rounds that also covered OOP and OS, then a hiring-manager round and an HR round.
- Some campus drives used an online test with aptitude as well as coding; one candidate said aptitude accuracy separated candidates.

### How your plan prepares you

- String algorithms (KMP) and Kadane: write them from memory
- Aptitude pack for campus tests
- Core CS one-pagers (OOP, OS) before the technical rounds

### Common mistakes

- Knowing an algorithm's idea but not being able to code it fully
- Skipping aptitude practice

### Questions to expect

- Implement KMP
- Maximum subarray (Kadane)
- Upper bound in a sorted array; all permutations

## Walmart Global Tech India (Software Engineer)

Recruits freshers on campus in India; campus posts list the fresher role as SDE-2 (Software Engineer II). Few 2025 fresher reports exist, so read new posts before your drive.

### What candidates report

- Campus drives in older reports: an online coding test (HackerEarth in one), then about 3 interview rounds.
- Rounds mix DSA (two LeetCode mediums in one report) with computer-science fundamentals: OOP, OS, SQL and networks; some include schema or system design.
- 2025 reviews found are mostly for experienced hires; treat the fresher details as indicative.

### How your plan prepares you

- Two mediums in 45 minutes: OA sets and DSA mocks
- Core CS one-pagers and the SQL pack for the fundamentals round
- System design one-pager for a light design question

### Common mistakes

- Neglecting SQL and networks because the OA is DSA

### Questions to expect

- Two medium DSA problems
- Design a schema for orders
- OOP, OS and SQL questions

## PhonePe (SDE-1)

Fintech in Bengaluru known for its machine-coding round. Clean, extensible, tested code matters as much as getting it working.

### What candidates report

- Machine coding: reports describe 60 to 90 minutes to build a working application (for example a customer-issue resolution system), with modular structure, validations, exception handling and sometimes concurrency.
- A follow-up review of your code: interviewers ask why you made each design choice and how it would scale or extend.
- DSA rounds also appear (a word-search-in-a-grid problem in one 2025 report).

### How your plan prepares you

- LLD pack: write each design again in 90 minutes without looking
- Backend starter: practise layering, validation and tests
- Run Mock 6 twice; practise explaining trade-offs aloud

### Common mistakes

- Code in one big class with no separation
- No input validation or error handling
- Not being able to justify a design decision

### Questions to expect

- Build an issue-tracking or booking system in 90 minutes
- Why this class structure? How would you add a new feature?
- Word search in a grid

## Zscaler (software engineer, security company)

A cloud-security company with large engineering teams in India; a natural target for your security profile. Reports describe a selective process with strong C/C++ and fundamentals.

### What candidates report

- Campus: an online coding round first (a Bengaluru C/C++ developer offer report), then technical interviews.
- Reports mention DSA, OOP, DBMS and C++ questions; one write-up describes an online assessment, a group discussion and two interviews.
- Pass rates in aggregated reports are low, but samples are small (3 to 9 reports).

### How your plan prepares you

- C++ depth: the STL card, the 30 bugs and the LLD code
- OS and networks one-pagers: a networking company asks about TCP, TLS and proxies
- TenantWall and the security lab notebook give you security stories

### Common mistakes

- Weak C++ details (memory, pointers, virtual functions)
- No security examples on the resume

### Questions to expect

- A medium DSA problem in C++
- Explain how TLS works
- Questions on OOP and DBMS
