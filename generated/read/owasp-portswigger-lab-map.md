## What changed since 2021

|                                       |                                                        |
|---------------------------------------|--------------------------------------------------------|
| Security Misconfiguration             | 5th → 2nd                                              |
| Software Supply Chain Failures        | new (grew out of 'Vulnerable and Outdated Components') |
| Cryptographic Failures                | 2nd → 4th                                              |
| Injection                             | 3rd → 5th                                              |
| Insecure Design                       | 4th → 6th                                              |
| SSRF                                  | own category in 2021 → part of Broken Access Control   |
| Logging                               | 'Monitoring' renamed 'Alerting'                        |
| Mishandling of Exceptional Conditions | new at 10th                                            |

Broken Access Control stays first. Sources: OWASP Top 10:2025 introduction and summaries from Orca Security, Invicti and GitLab (links on the last page).

## 10 web-security interview questions

|     |                                                                          |                                                                                                                                                                                                                                             |
|-----|--------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 1   | What is the difference between authentication and authorisation?         | Authentication proves who you are (login); authorisation decides what you may do. Broken access control (A01) is an authorisation failure: logged in, but allowed too much.                                                                 |
| 2   | How do you prevent SQL injection?                                        | Parameterised queries so input is never parsed as SQL; least-privilege database accounts; input validation as a second layer. Escaping by hand is fragile.                                                                                  |
| 3   | Stored vs reflected vs DOM-based XSS?                                    | Stored is saved on the server and shown to others; reflected comes back in the response to the attacker's link; DOM-based happens entirely in client-side JavaScript. Fix with context-aware output encoding and a Content Security Policy. |
| 4   | How does CSRF work and how do you stop it?                               | The browser sends cookies automatically, so another site can trigger state-changing requests. Use anti-CSRF tokens, SameSite cookies and re-authentication for sensitive actions.                                                           |
| 5   | What is SSRF and why is it dangerous in the cloud?                       | The server fetches a URL the attacker controls, reaching internal services or the cloud metadata endpoint, which can expose credentials. Allowlist destinations and block internal ranges; on AWS require IMDSv2.                           |
| 6   | What is IDOR?                                                            | Insecure direct object reference: changing an id in a request returns someone else's data because the server does not check ownership. Check ownership on every request (as the backend starter does).                                      |
| 7   | How should passwords be stored?                                          | A slow, salted hash (Argon2id, scrypt or bcrypt), compared in constant time; never plain text or a fast hash such as SHA-256 alone.                                                                                                         |
| 8   | What makes a JWT implementation insecure?                                | Accepting alg: none or switching algorithms, weak HMAC secrets, not checking expiry, or trusting unverified claims. Fix the algorithm list and verify signature and expiry.                                                                 |
| 9   | What is the same-origin policy, and what does CORS change?               | Scripts can only read responses from their own origin; CORS lets a server allow named other origins. Reflecting any Origin with credentials allowed defeats the protection.                                                                 |
| 10  | How would you find vulnerabilities in a web app you are allowed to test? | Map it (Burp proxy, every request), list inputs and trust boundaries, test each OWASP category on the riskiest features first, confirm impact safely, and write up the fix. Only with permission.                                           |
